# Бот кружков и улучшения фото

Облачный Python-проект. Для пилота выбран blitz.cloud; аккаунт подтверждён.
Бот ещё не подключён к Telegram и не развёрнут.
Текущий код — основа для пилота, а не подтверждённый сервис без ограничений.
Сравнение бесплатных площадок без карты: [docs/HOSTING.md](docs/HOSTING.md).

## Возможности

- Видео/анимации/видеофайлы → последовательно отправляемые кружки до 60 секунд.
- Кнопки меню: кружки, фото, нейрорежим, бережный режим, увеличение, кадрирование,
  статус, отмена и помощь. Команды также работают.
- H.264, AAC, 640×640, CRF 18; поворот телефона обрабатывает FFmpeg.
- По умолчанию preset `veryfast`: меньше затрат CPU при той же настройке CRF.
  Степень сжатия и качество могут немного отличаться от `fast`.
  `/status` показывает длительности очереди, скачивания, обработки и отправки
  текущего либо последнего задания; измерения хранятся только в памяти.
- Кружки кодируются с ограничением примерно 19 МБ на 60 секунд, чтобы оставался
  запас до лимита Telegram; качество сохраняется настолько, насколько позволяет
  этот размер.
- Заполнение круга с обрезкой или сохранение всего кадра внутри видимой окружности.
- Обрезка берёт максимальный центральный квадрат до масштабирования. Кнопка
  «Кружки» включает этот режим без полей.
- Фото и файлы изображений → PNG без повторного сжатия Telegram.
- Бережное увеличение ×2/×4 по умолчанию; опционально компактный Real-ESRGAN,
  без отдельной модели восстановления лица. AI может менять детали — гарантии
  сохранения всех черт нет. Размер выхода ограничен памятью сервера.
- В AI-режиме нейросеть получает копию с длинной стороной до 512 пикселей;
  результат смешивается с увеличенным оригиналом. Это ограничивает расходы
  памяти и CPU, но ограничивает нейродетализацию больших фотографий.
- Доступ только OWNER_ID в личном чате, очередь из трёх ожидающих заданий,
  отмена, тайм-аут, очистка временных каталогов при успехе/ошибке/следующем старте.

## Запуск в облаке

Нужны токен из @BotFather и числовой Telegram ID владельца. Это отдельный бот;
доступ к ChatGPT и к личной сессии Telegram не используется.

Образ собирается из `Dockerfile`, работает от uid 1000. PyTorch используется
только во время сборки ONNX; при работе изображения обрабатывает ONNX Runtime CPU.
Сборка загружает открытые веса, не пользовательские медиа.

1. Разместить код без `.env`, `.venv`, `runtime`, моделей и секретов в Git-репозитории.
2. В облаке выбрать Dockerfile и только бесплатный тариф.
3. Внести `BOT_TOKEN`, `OWNER_ID` в секреты приложения.
4. Для фонового бота: `DELIVERY=polling`. Для blitz.cloud выбрать
   **Runs in the background**, без адреса. Размещение на нём пока не проверено.
5. Для Render: использовать `render.yaml`, режим webhook; PUBLIC_URL автоматически
   берётся из RENDER_EXTERNAL_URL. WEBHOOK_SECRET генерирует Blueprint.
6. При первой проверке послать `/start`, короткое видео и небольшую фотографию.
   Затем `/mode ai` и ту же фотографию. Оценить изменения деталей самостоятельно.

Без отдельно подключённого Local Bot API действует входной лимит 20 МБ. Файл,
который уже больше 20 МБ, нельзя сжать внутри бота: Telegram не передаёт его
боту. Пользователь должен отправить предварительно сжатую копию.
`MAX_INPUT_MB` сам по себе не обходит ограничение Telegram.
В режиме собственного Bot API `MAX_INPUT_MB=0` снимает фиксированный лимит
приложения. Перед скачиванием проверяется свободный диск; это не обещание
неограниченного размера. На официальном API значение 0 оставляет предел 20 МБ.
Для больших файлов нужен облачный сервер Local Bot API и дополнительные
TELEGRAM_API_ID / TELEGRAM_API_HASH из my.telegram.org. Подключение предусмотрено
через BOT_API_URL и LOCAL_FILES_ROOT, но развёртывание и очистка всех кешей этого
сервера пока не реализованы как готовая конфигурация. Не публиковать его API-порт.

## Конфиденциальность и ограничения

Приложение не создаёт галерею, базу фотографий, публичные ссылки или историю медиа.
Временные файлы находятся в WORK_DIR, в отдельных job-каталогах, и удаляются
после отправки или ошибки. При аварийном убийстве процесса они удаляются при
следующем запуске. Не подключать WORK_DIR к резервному копированию.

Это логическое удаление файлов, не гарантия физического стирания SSD, swap,
снимков облака или данных Telegram. Сам Telegram хранит сообщения и вложения.
При подключении Local Bot API его кеш требует отдельного контроля; обработчик
удаляет только полученный исходный файл в разрешённом общем каталоге.

Уведомления webhook принимаются только с секретом Telegram. Медиа, пути,
имена исходников, токены и тела обновлений намеренно не записываются в логи.

Очередь и настройки находятся в памяти и теряются при перезапуске. Уже
подтверждённое Telegram задание при аварии нужно отправить заново. При
неоднозначном сетевом сбое отправки нет автоматического повтора, который мог бы
создать дубли. Бесплатный хостинг может прервать процесс при нехватке памяти.
Количество и размер файлов ограничены Telegram, диском и временем обработки.

Поддерживаются форматы, распознаваемые установленными FFmpeg и Pillow, а не
любой существующий кодек. HEIC/RAW не входят в гарантированный набор.
HDR → SDR с контролируемым тональным отображением пока не реализовано.

## Проверка разработки

Python 3.12, FFmpeg и ffprobe в PATH. Установить requirements.txt и pytest.
`python -m pytest -q` проверяет доступ, очередь, отмену, очистку и изображения.
`python scripts/export_model.py` (нужны torch==2.7.1 и onnx==1.18.0)
создаёт ONNX и сравнивает результат с оригинальной сетью.

Реальное тестирование в Telegram и тесты памяти/скорости выбранного облака
нужны до объявления продукта готовым.

Проверено в среде разработки 28.09.2026: **27 тестов прошли**. В том числе
реальная конвертация двух синтетических видео на 125 секунд (со звуком/без звука)
в три кружка, контроль формата и длительности, нейроапскейл с проверкой стыков
фрагментов и численное сравнение ONNX с исходной сетью. Это не измерение
производительности облака на 512 МБ. Docker-сборка здесь не запускалась:
Docker Engine недоступен. Доставка через настоящий Telegram пока не проверена.
